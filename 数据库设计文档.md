# 竹签自动计价系统 - 数据库设计文档

***

## 一、总体设计

### 1.1 数据库选型

| 项    | 选型                   | 说明              |
| ---- | -------------------- | --------------- |
| 数据库  | MySQL 8.0+           | 事务支持完善，运维成熟     |
| 字符集  | `utf8mb4`            | 兼容 emoji 与生僻字   |
| 排序规则 | `utf8mb4_unicode_ci` | 大小写不敏感，符合中文检索习惯 |
| 存储引擎 | InnoDB               | 支持外键与行级锁        |
| 连接端口 | 3306                 | <br />          |

### 1.2 命名约定

- 库名：`skewer_count`，全小写下划线。
- 表名：全小写复数形式（`users`、`orders`、`price_config`、`audit_log`）。
- 字段名：全小写下划线（`created_at`、`unit_price`）。
- 主键：统一 `id`，BigInteger 自增（避免外键类型不兼容问题）。
- 外键：`<关联表单数>_id`（如 `staff_id` 关联 `users.id`）。
- 时间字段：`created_at` / `updated_at`，DateTime 类型。
- 状态字段：`status` / `is_active`，SmallInteger，0/1 表示。
- 订单号、流水号：业务字段，前缀 + 日期 + 流水号（`ORD20260630000001`）。

### 1.3 公共字段

所有业务表继承自 `TimestampMixin` 或自带时间字段，统一包含：

| 字段           | 类型       | 说明                          |
| ------------ | -------- | --------------------------- |
| `created_at` | DateTime | 创建时间，`server_default=now()` |
| `updated_at` | DateTime | 更新时间，`onupdate=now()`       |

### 1.4 多店设计核心思路

**每个管理员 = 一家店**，不引入独立的 `stores` 表。

- `users.admin_id` 自引用外键：
  - 管理员：`admin_id = NULL`
  - 员工：`admin_id = 创建该员工的管理员 id`
- `price_config.admin_id`：价格归属到管理员/店，每店独立维护价格历史。
- `orders.admin_id`：订单归属到管理员/店，方便管理员查询本店订单、统计、导出。
- 所有管理员侧的查询接口（员工列表、订单、统计、导出）均按 `admin_id` 过滤，确保多店数据隔离。

**关系说明：**

| 关系                             | 基数    | 说明                                                   |
| ------------------------------ | ----- | ---------------------------------------------------- |
| `users` → `users` (admin\_id)  | 1 : N | 一个管理员可拥有多个员工，员工通过 `admin_id` 自引用管理员                  |
| `users` → `orders` (staff\_id) | 1 : N | 一个员工可创建多个订单，`orders.staff_id` 指向 `users.id`          |
| `users` → `orders` (admin\_id) | 1 : N | 一个管理员/店拥有多个订单，`orders.admin_id` 指向 `users.id`，用于数据隔离 |
| `users` → `price_config`       | 1 : N | 一个管理员可设置多次价格，`price_config.admin_id` 指向 `users.id`   |
| `users` → `audit_log`          | 1 : N | 一个用户可产生多条操作日志，`audit_log.user_id` 可空                 |

## 三、表结构详细设计

### 3.1 用户表 `users`

**用途：** 统一存储管理员与员工账号。每个管理员代表一家店，员工通过 `admin_id` 绑定到所属管理员/店。

| 字段                     | 类型           | 允许空 | 默认              | 索引     | 说明                          |
| ---------------------- | ------------ | --- | --------------- | ------ | --------------------------- |
| `id`                   | BIGINT       | 否   | AUTO\_INCREMENT | PK     | 主键                          |
| `username`             | VARCHAR(32)  | 否   | -               | UNIQUE | 账号/工号，全局唯一                  |
| `password_hash`        | VARCHAR(128) | 否   | -               | -      | bcrypt 哈希（含 salt）           |
| `name`                 | VARCHAR(32)  | 否   | -               | -      | 真实姓名                        |
| `role`                 | SMALLINT     | 否   | 1               | -      | 1=管理员，2=员工                  |
| `admin_id`             | BIGINT       | 是   | NULL            | INDEX  | 员工所属管理员/店；管理员自身为 NULL。自引用外键 |
| `is_active`            | SMALLINT     | 否   | 1               | -      | 1=启用，0=停用                   |
| `must_change_password` | SMALLINT     | 否   | 0               | -      | 1=下次登录强制改密                  |
| `deleted_at`           | DATETIME     | 是   | NULL            | -      | 软删除时间，NULL=未删除              |
| `created_at`           | DATETIME     | 否   | NOW             | -      | 创建时间                        |
| `updated_at`           | DATETIME     | 否   | NOW             | -      | 更新时间                        |

**业务约束：**

- `username` 唯一性由数据库 UNIQUE 约束保证，注册并发不会冲突。
- `password_hash` 永不返回给前端，序列化层显式排除。
- 删除员工时**不级联删除订单**，`orders.staff_id` 保留，仅员工账号软停用（`deleted_at` + `is_active=0` + `username` 加 `deleted_` 前缀避免冲突）。
- 管理员注册时 `must_change_password=0`，员工首次创建时 `=1`。
- **多店隔离：** 员工必须绑定 `admin_id`；管理员自身 `admin_id` 为 NULL。

**外键关系：**

```sql
CONSTRAINT fk_users_admin
  FOREIGN KEY (admin_id) REFERENCES users(id)
  ON DELETE RESTRICT ON UPDATE CASCADE
```

> 自引用外键。删除管理员时数据库层禁止（`RESTRICT`），业务层通过软删除处理。

### 3.2 价格配置表 `price_config`

**用途：** 记录每个管理员/店的竹签单价变更历史。修改单价后立即生效。

| 字段               | 类型            | 允许空 | 默认              | 索引    | 说明             |
| ---------------- | ------------- | --- | --------------- | ----- | -------------- |
| `id`             | BIGINT        | 否   | AUTO\_INCREMENT | PK    | 主键             |
| `admin_id`       | BIGINT        | 否   | -               | INDEX | 所属管理员/店        |
| `skewer_type`    | VARCHAR(16)   | 否   | -               | INDEX | 固定为 `bamboo`   |
| `unit_price`     | DECIMAL(10,2) | 否   | -               | -     | 单价（元）          |
| `effective_date` | DATE          | 否   | -               | INDEX | 设置日期（仅记录，立即生效） |
| `created_at`     | DATETIME      | 否   | NOW             | -     | 设置时间           |

**业务约束：**

- **立即生效：** 修改单价后立即生效，当前价格 = 该店最新一条记录（按 `id` 倒序）。
- **不再有日期约束：** 同一天可多次设置价格，每次新增一条记录，无 `(admin_id, skewer_type, effective_date)` 唯一约束。
- **不影响历史订单：** 订单生成时把当前价格快照写入 `orders.unit_price`，后续调价不影响历史订单金额。
- **不可删除：** 价格变更记录需保留审计痕迹，只增不改不删。
- **多店隔离：** 每个 `admin_id` 维护自己的价格历史。

**查询本店当前价格的 SQL：**

```sql
SELECT unit_price
FROM price_config
WHERE admin_id = ?
  AND skewer_type = 'bamboo'
ORDER BY id DESC
LIMIT 1;
```

### 3.3 订单表 `orders`

**用途：** 记录每一笔竹签计数订单。订单归属到管理员/店，便于多店数据隔离。

| 字段             | 类型            | 允许空 | 默认              | 索引     | 说明                                |
| -------------- | ------------- | --- | --------------- | ------ | --------------------------------- |
| `id`           | BIGINT        | 否   | AUTO\_INCREMENT | PK     | 主键                                |
| `order_no`     | VARCHAR(32)   | 否   | -               | UNIQUE | 订单号，`ORD+yyyyMMdd+6位流水`           |
| `staff_id`     | BIGINT        | 否   | -               | INDEX  | 员工 `users.id` 外键                  |
| `admin_id`     | BIGINT        | 否   | -               | INDEX  | 所属管理员/店 `users.id` 外键             |
| `bamboo_count` | INT           | 否   | -               | -      | 竹签数量                              |
| `unit_price`   | DECIMAL(10,2) | 否   | -               | -      | 生成时锁定的竹签单价快照                      |
| `total_amount` | DECIMAL(10,2) | 否   | -               | -      | 总金额 = `bamboo_count * unit_price` |
| `image_path`   | VARCHAR(255)  | 是   | NULL            | -      | 压缩图相对路径，撤销后置空                     |
| `remark`       | VARCHAR(200)  | 是   | NULL            | -      | 备注                                |
| `status`       | SMALLINT      | 否   | 1               | -      | 1=有效，0=已撤销                        |
| `cancelled_at` | DATETIME      | 是   | NULL            | -      | 撤销时间                              |
| `created_at`   | DATETIME      | 否   | NOW             | INDEX  | 创建时间                              |
| `updated_at`   | DATETIME      | 否   | NOW             | -      | 更新时间                              |

**复合索引：**

| 索引名                 | 字段                       | 用途                 |
| ------------------- | ------------------------ | ------------------ |
| `idx_staff_created` | `(staff_id, created_at)` | 加速员工查询自己的订单（按时间倒序） |
| `idx_admin_created` | `(admin_id, created_at)` | 加速管理员查询本店订单（按时间倒序） |

**业务约束：**

- **订单号生成规则：** `ORD` + `yyyyMMdd` + 6 位日内流水号（`000001` 起），全局唯一。
- **金额计算：** 后端在生成订单时计算 `total_amount = bamboo_count * unit_price`，不依赖前端传入，避免篡改。
- **价格快照：** 生成订单时把当前单价复制到 `unit_price`，后续调价**不影响历史订单**。
- **订单归属：** 生成订单时 `admin_id = staff.admin_id`，确保订单归属到员工所属的店。
- **撤销规则：** 撤销仅置 `status=0`、`cancelled_at=NOW()`、`image_path=NULL`，**不物理删除**，原图由定时任务清理。
- **跨店保护：** 管理员撤销订单时校验 `order.admin_id == admin.id`，无权撤销其他店的订单。
- **不可修改：** 订单一旦生成，数量、金额、单价均不可修改；员工仅能改 `remark`。

**外键关系：**

```sql
CONSTRAINT fk_orders_staff
  FOREIGN KEY (staff_id) REFERENCES users(id)
  ON DELETE RESTRICT ON UPDATE CASCADE,
CONSTRAINT fk_orders_admin
  FOREIGN KEY (admin_id) REFERENCES users(id)
  ON DELETE RESTRICT ON UPDATE CASCADE
```

> 删除员工时数据库层禁止（`RESTRICT`），业务层通过软停用处理。

### 3.4 审计日志表 `audit_log`

**用途：** 记录敏感操作，便于管理员追溯。

| 字段           | 类型          | 允许空 | 默认              | 索引    | 说明                    |
| ------------ | ----------- | --- | --------------- | ----- | --------------------- |
| `id`         | BIGINT      | 否   | AUTO\_INCREMENT | PK    | 主键                    |
| `user_id`    | BIGINT      | 是   | NULL            | -     | 操作人 `users.id`，系统操作为空 |
| `order_no`   | VARCHAR(32) | 是   | NULL            | INDEX | 关联订单号                 |
| `action`     | VARCHAR(32) | 否   | -               | INDEX | 动作类型                  |
| `detail`     | TEXT        | 是   | NULL            | -     | 详情（JSON 字符串）          |
| `created_at` | DATETIME    | 否   | NOW             | INDEX | 操作时间                  |

**`action`** **取值约定：**

| action 值                 | 触发场景    | detail 示例                                         |
| ------------------------ | ------- | ------------------------------------------------- |
| `create_employee`        | 管理员新增员工 | `"管理员 admin 新增员工 staff001(张三)"`                   |
| `delete_employee`        | 管理员删除员工 | `"管理员 admin 删除员工 staff001(张三)"`                   |
| `toggle_employee_status` | 启用/停用员工 | `"管理员 admin 启用员工 staff001"`                       |
| `update_price`           | 修改竹签单价  | `'{"admin_id":1,"type":"bamboo","price":"0.50"}'` |
| `cancel_order`           | 撤销订单    | `'{"order_no":"ORD20260630000001","staff_id":3}'` |

**业务约束：**

- `user_id` 可空，兼容系统自动触发的操作（如定时清理图片）。
- **只增不删不改**，审计日志永久保留。
- `detail` 字段建议存 JSON 字符串，便于后续扩展。

## 四、索引设计

### 4.1 索引清单

| 表              | 索引名                                | 字段                       | 类型     | 用途           |
| -------------- | ---------------------------------- | ------------------------ | ------ | ------------ |
| `users`        | PRIMARY                            | `id`                     | BTREE  | 主键           |
| `users`        | uk\_username                       | `username`               | UNIQUE | 账号唯一性 + 登录查询 |
| `users`        | ix\_users\_admin\_id               | `admin_id`               | BTREE  | 按管理员查员工列表    |
| `orders`       | PRIMARY                            | `id`                     | BTREE  | 主键           |
| `orders`       | uk\_order\_no                      | `order_no`               | UNIQUE | 订单号唯一 + 查询   |
| `orders`       | idx\_staff\_created                | `(staff_id, created_at)` | BTREE  | 员工查自己订单（高频）  |
| `orders`       | idx\_admin\_created                | `(admin_id, created_at)` | BTREE  | 管理员查本店订单（高频） |
| `orders`       | ix\_orders\_created\_at            | `created_at`             | BTREE  | 按日期统计        |
| `price_config` | PRIMARY                            | `id`                     | BTREE  | 主键           |
| `price_config` | ix\_price\_config\_admin\_id       | `admin_id`               | BTREE  | 按店查询价格       |
| `price_config` | ix\_price\_config\_skewer\_type    | `skewer_type`            | BTREE  | 按类型查询        |
| `price_config` | ix\_price\_config\_effective\_date | `effective_date`         | BTREE  | 历史保留         |
| `audit_log`    | PRIMARY                            | `id`                     | BTREE  | 主键           |
| `audit_log`    | idx\_action                        | `action`                 | BTREE  | 按动作类型筛选      |
| `audit_log`    | idx\_order\_no                     | `order_no`               | BTREE  | 查订单相关日志      |
| `audit_log`    | idx\_created\_at                   | `created_at`             | BTREE  | 按时间范围查日志     |

### 4.2 索引设计原则

1. **高频查询优先：** `(admin_id, created_at)` 复合索引覆盖管理员查本店订单的高频场景；`(staff_id, created_at)` 覆盖员工查自己订单。
2. **唯一性约束：** `username`、`order_no` 通过 UNIQUE 索引保证业务唯一性。
3. **多店隔离索引：** `users.admin_id`、`orders.admin_id`、`price_config.admin_id` 都建索引，保证按店过滤的查询性能。
4. **外键自动建索引：** MySQL InnoDB 自动为外键列创建索引，无需重复声明。

## 五、数据流转示例

### 5.1 订单生成全流程（多店场景）

```
员工 staff001 (admin_id=5) 上传图片 → AI 计数 → 竹签 142 根
                  │
                  ▼
        查询本店（admin_id=5）当前价格
        ┌──────────────────────────────┐
        │ SELECT unit_price            │
        │ FROM price_config            │
        │ WHERE admin_id=5             │
        │   AND skewer_type='bamboo'   │
        │ ORDER BY id DESC LIMIT 1     │
        │ → 0.50                       │
        └──────────────────────────────┘
                  │
                  ▼
        计算总金额 = 142 × 0.50 = 71.00
                  │
                  ▼
        INSERT INTO orders (
          order_no='ORD20260630000002',
          staff_id=3,
          admin_id=5,            ← 来自 staff.admin_id
          bamboo_count=142,
          unit_price=0.50,       ← 价格快照
          total_amount=71.00,
          status=1
        )
```

### 5.2 价格修改对历史订单的影响（立即生效）

```
Day 1 上午: 本店设置单价 0.50 → 生成订单 A (unit_price=0.50, total=71.00)
Day 1 下午: 本店再次设置单价 0.60 → 立即生效
Day 1 晚上: 生成订单 B (unit_price=0.60, total=85.20)

结果：
  订单 A 金额仍为 71.00（不受影响，价格快照）
  订单 B 金额为 85.20（按新价）
  本店当前价 = price_config 最新一条（id 最大）= 0.60
```

### 5.3 多店隔离示例

```
管理员 A (id=1) 设置本店单价 0.50
管理员 B (id=2) 设置本店单价 0.80

管理员 A 查询当前价 → 0.50
管理员 B 查询当前价 → 0.80

管理员 A 创建的员工 (admin_id=1) 生成订单 → 用 0.50
管理员 B 创建的员工 (admin_id=2) 生成订单 → 用 0.80

管理员 A 查询订单/统计/导出 → 只能看到 admin_id=1 的订单
管理员 B 查询订单/统计/导出 → 只能看到 admin_id=2 的订单
```

### 5.4 订单撤销流程

```
员工/管理员撤销订单 A
        │
        ▼
UPDATE orders
SET status=0,
    cancelled_at=NOW(),
    image_path=NULL,
    updated_at=NOW()
WHERE id=1 AND status=1 AND admin_id=?

INSERT INTO audit_log (user_id, order_no, action, detail)
VALUES (?, 'ORD20260630000001', 'cancel_order', '{...}')

定时任务（每日凌晨）扫描无引用的图片文件并删除
```

## 六、迁移管理

- **Alembic**（SQLAlchemy 官方迁移工具）
- 配置文件：`backend/alembic.ini`
- 迁移脚本目录：`backend/alembic/versions/`
- **开发期初始化脚本：** `backend/scripts/init_db.py`（DROP + CREATE + 默认管理员）

### 6.2 常用命令

```bash
# 开发期快速重建（清空所有数据！）
cd backend
d:\code\program\venv\Scripts\python.exe -m scripts.init_db

python -m alembic revision --autogenerate -m "描述变更内容"
python -m alembic upgrade head
python -m alembic downgrade -1
python -m alembic current
python -m alembic history
```

### 6.4 迁移规范

1. **每次模型变更必须生成迁移脚本**（生产环境），不可手动改库结构。
2. **生产环境迁移前必须备份**：`mysqldump -u root -p skewer_count > backup_$(date +%Y%m%d).sql`。
3. **迁移脚本一旦提交不可修改**，新变更通过新版本追加。
4. **数据迁移与结构迁移分离**：结构变更通过 `op.add_column()` 等，数据填充单独脚本。
5. **开发期可用** **`scripts/init_db.py`** **快速重建**，会清空所有数据。

## 七、安全与备份

### 7.1 权限控制

| 账号                | 权限范围                                              | 用途             |
| ----------------- | ------------------------------------------------- | -------------- |
| `root`            | 全部                                                | 仅开发/初始化使用，生产禁用 |
| `skewer_app`      | `SELECT/INSERT/UPDATE/DELETE` on `skewer_count.*` | 应用运行账号         |
| `skewer_readonly` | `SELECT` on `skewer_count.*`                      | 报表查询           |

### 7.2 备份策略

| 类型        | 频率       | 保留期  | 命令                                            |
| --------- | -------- | ---- | --------------------------------------------- |
| 全量备份      | 每日凌晨 2 点 | 30 天 | `mysqldump --single-transaction skewer_count` |
| Binlog 备份 | 实时       | 7 天  | MySQL 主从复制或 binlog dump                       |
| 手动备份      | 迁移前      | 永久   | `mysqldump skewer_count > pre_migration.sql`  |

### 7.3 敏感数据处理

| 字段                 | 处理方式                      |
| ------------------ | ------------------------- |
| `password_hash`    | bcrypt 哈希存储，不可逆；API 响应中排除 |
| `image_path`       | 撤销订单后置空；原图由定时任务物理删除       |
| `audit_log.detail` | 保留完整操作痕迹，不脱敏              |

### 7.4 多店数据隔离

| 接口         | 隔离方式                                                     |
| ---------- | -------------------------------------------------------- |
| 员工列表       | `User.admin_id == admin.id`                              |
| 订单列表/统计/导出 | `Order.admin_id == admin.id`                             |
| 价格设置/历史    | `PriceConfig.admin_id == admin.id`                       |
| 员工生成订单     | `Order.admin_id = staff.admin_id`；查询价格按 `staff.admin_id` |
| 撤销订单       | 校验 `order.admin_id == admin.id`，跨店禁止                     |

### 8.1 完整建表 SQL（参考）

> 实际生产以 Alembic 迁移脚本为准；开发期以 `scripts/init_db.py` 为准。以下仅作设计参考。

```sql
-- 用户表（自引用：admin_id → users.id）
CREATE TABLE users (
  id BIGINT NOT NULL AUTO_INCREMENT,
  username VARCHAR(32) NOT NULL,
  password_hash VARCHAR(128) NOT NULL,
  name VARCHAR(32) NOT NULL,
  role SMALLINT NOT NULL DEFAULT 1 COMMENT '1=管理员, 2=员工',
  admin_id BIGINT DEFAULT NULL COMMENT '员工所属管理员/店；管理员自身为 NULL',
  is_active SMALLINT NOT NULL DEFAULT 1 COMMENT '1=启用, 0=停用',
  must_change_password SMALLINT NOT NULL DEFAULT 0 COMMENT '1=下次登录强制改密',
  deleted_at DATETIME DEFAULT NULL COMMENT '软删除时间',
  created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  PRIMARY KEY (id),
  UNIQUE KEY uk_username (username),
  KEY ix_users_admin_id (admin_id),
  CONSTRAINT fk_users_admin FOREIGN KEY (admin_id) REFERENCES users(id)
    ON DELETE RESTRICT ON UPDATE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='用户表';

-- 价格配置表（每店独立）
CREATE TABLE price_config (
  id BIGINT NOT NULL AUTO_INCREMENT,
  admin_id BIGINT NOT NULL COMMENT '所属管理员/店',
  skewer_type VARCHAR(16) NOT NULL COMMENT '固定为 bamboo',
  unit_price DECIMAL(10,2) NOT NULL COMMENT '单价（元）',
  effective_date DATE NOT NULL COMMENT '设置日期（仅记录，立即生效）',
  created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (id),
  KEY ix_price_config_admin_id (admin_id),
  KEY ix_price_config_skewer_type (skewer_type),
  KEY ix_price_config_effective_date (effective_date),
  CONSTRAINT fk_price_admin FOREIGN KEY (admin_id) REFERENCES users(id)
    ON DELETE RESTRICT ON UPDATE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='价格配置表';

-- 订单表（归属到管理员/店）
CREATE TABLE orders (
  id BIGINT NOT NULL AUTO_INCREMENT,
  order_no VARCHAR(32) NOT NULL COMMENT '订单号 ORD+yyyyMMdd+6位流水',
  staff_id BIGINT NOT NULL,
  admin_id BIGINT NOT NULL COMMENT '所属管理员/店',
  bamboo_count INT NOT NULL COMMENT '竹签数量',
  unit_price DECIMAL(10,2) NOT NULL COMMENT '生成时锁定的竹签单价快照',
  total_amount DECIMAL(10,2) NOT NULL COMMENT '金额 = bamboo*unit_price',
  image_path VARCHAR(255) DEFAULT NULL COMMENT '压缩图相对路径',
  remark VARCHAR(200) DEFAULT NULL COMMENT '备注',
  status SMALLINT NOT NULL DEFAULT 1 COMMENT '1=有效, 0=已撤销',
  cancelled_at DATETIME DEFAULT NULL COMMENT '撤销时间',
  created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  PRIMARY KEY (id),
  UNIQUE KEY uk_order_no (order_no),
  KEY idx_staff_created (staff_id, created_at),
  KEY idx_admin_created (admin_id, created_at),
  KEY ix_orders_created_at (created_at),
  CONSTRAINT fk_orders_staff FOREIGN KEY (staff_id) REFERENCES users(id)
    ON DELETE RESTRICT ON UPDATE CASCADE,
  CONSTRAINT fk_orders_admin FOREIGN KEY (admin_id) REFERENCES users(id)
    ON DELETE RESTRICT ON UPDATE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='订单表';

-- 审计日志表
CREATE TABLE audit_log (
  id BIGINT NOT NULL AUTO_INCREMENT,
  user_id BIGINT DEFAULT NULL COMMENT '操作人，系统操作为空',
  order_no VARCHAR(32) DEFAULT NULL COMMENT '关联订单号',
  action VARCHAR(32) NOT NULL COMMENT '动作类型',
  detail TEXT COMMENT '详情 JSON',
  created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (id),
  KEY idx_action (action),
  KEY idx_order_no (order_no),
  KEY idx_created_at (created_at),
  CONSTRAINT fk_audit_user FOREIGN KEY (user_id) REFERENCES users(id)
    ON DELETE SET NULL ON UPDATE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='审计日志表';
```

### 8.3 术语表

| 术语         | 说明                                               |
| ---------- | ------------------------------------------------ |
| 竹签（bamboo） | 一次性竹制签子，按根计价（系统唯一识别类型）                           |
| 价格快照       | 订单生成时复制的当时单价，写入订单表，不随后续调价变化                      |
| 软删除        | 通过 `status=0` 或 `deleted_at` 标记而非物理删除，保留审计痕迹     |
| 强制改密       | `must_change_password=1` 时，登录后必须先改密才能进入业务页面      |
| 多店隔离       | 每个管理员代表一家店，所有数据（员工/订单/价格）按 `admin_id` 隔离         |
| 自引用外键      | `users.admin_id` 指向 `users.id`，员工通过此字段绑定到所属管理员/店 |
